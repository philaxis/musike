# Design: 서버판 Musike

## 지금 모양

- 곡(`Track`)의 번호는 유튜브 영상 ID(11자, `VIDEO_ID`)뿐이다. 서버 API(`/api/stream/:id`, `/api/prepare/:id`, 즐겨찾기·재생목록 삭제)와 `sanitizeTrack`이 모두 이 규칙으로 막는다.
- 웹 플레이어는 소리 모드에 `<audio>`, 영상 모드에 `<video>` 하나를 쓰고, 되감기는 `player.seek()` 한 곳에서 처리하며 잠금화면 조작(Media Session)을 한다.
- 서버에는 구간 요청으로 파일을 보내는 `serveFile`이 이미 있다(HD 영상 캐시용).

## 결정

### 1. 로컬 곡 번호
- 로컬 곡 번호는 `L` + 20자(base64url, `sha256(뿌리 이름 + "/" + 뿌리 안 상대 경로)` 앞부분)다. 유튜브 ID(11자)와 길이·첫 글자로 겹치지 않는다. `TRACK_ID = VIDEO_ID 또는 /^L[A-Za-z0-9_-]{20}$/`로 바꾸고, 유튜브만 되는 API(라디오, 뮤직비디오 찾기)는 `VIDEO_ID`를 그대로 쓴다.
- 같은 파일은 경로가 그대로면 번호가 그대로다. 이름이 바뀐 파일은 새 곡이 되고, 재생목록에 남은 옛 번호는 「사라진 파일」로 흐리게 보이며 틀 때 건너뛴다.
- `Track`에 `source?: "local"`를 더한다. 표지(`thumb`, `art`)는 `https://`만 받던 규칙에 `/api/local/<번호>/cover`(같은 서버 상대 주소)를 더한다.

### 2. 읽을 폴더
- 환경변수 `MUSIKE_LOCAL_DIRS`에 `이름=경로`를 `;`로 잇는다. 처음 값:
  - `야마시타 타츠로=/mnt/backup8t/gdrive/current/MUSICS/야마시타 타츠로`
  - `카시오페아=/mnt/backup8t/gdrive/current/MUSICS/카시오페아`
  - `유튜브 보관함=/home/philaxis/보관함/유튜브` (yt-bulk가 받는 곳)
  - `받아 둔 곡=/mnt/backup8t/orca-data/musike/keep`
- 읽기 전용이다. 서버는 이 폴더에 아무것도 쓰지 않는다(받아 둔 곡 폴더만 예외). 구글 드라이브 사본이 다시 맞춰질 때 지우거나 덮을 일이 없게 하기 위해서다.
- 소리·영상 확장자(mp4, m4a, mkv, webm, mp3, flac, opus, ogg, wav)만 곡이 된다. `.f251.webm`처럼 yt-dlp가 남긴 반쪽 파일(영상만·소리만 조각)은 같은 이름의 합친 파일이 있으면 뺀다.
- 서버가 켜질 때와 10분마다 폴더를 훑는다. 새로 생긴 파일만 `ffprobe`로 길이·태그·영상 유무를 읽고, 결과는 데이터 폴더의 `local-index.json`(작음)에 둔다. 폴더가 없으면(HDD가 안 붙음) 그 뿌리를 「지금 못 읽음」으로 표시하고 색인은 지우지 않는다.

### 3. 곡 이름 만들기
- 제목: 태그 `title`이 있으면 그것, 없으면 파일 이름에서 `[1980.09.21]` 같은 앞 날짜와 `(Lossless)`·`(320 Kbps)` 같은 음질 꼬리를 뺀 것.
- 가수: 태그 `artist`, 없으면 뿌리 이름(예: 야마시타 타츠로). 유튜브 보관함은 채널 폴더 이름.
- 앨범: 태그 `album`, 없으면 파일이 든 폴더 이름. 앨범 mp4 하나짜리는 앨범 칸을 비운다.
- 연도: 파일 이름 앞 날짜나 태그 `date`. 「내 음악」에서 앨범은 연도순.
- 표지: 같은 폴더의 `folder.jpg`·`cover.jpg`, 없으면 영상의 5초 지점 한 장을 400px로 떠서 캐시(곡당 수십 KB)에 둔다.

### 4. 로컬 곡 재생
- 영상 모드: `serveFile`로 파일을 그대로 보낸다(구간 요청, 되감기 자유).
- 소리 모드(추천안, 판정 필요): 서버가 `ffmpeg -ss <t> -i 파일 -map 0:a:0 -c copy -f mp4 -movflags frag_keyframe+empty_moov` 출력을 그대로 흘려보낸다. 재인코딩이 없어 서버 부담이 거의 없고, 디스크에 쓰지 않는다. 앨범 mp4(영상 약 0.9Mbps + 소리 0.32Mbps)를 소리만 보내면 데이터가 약 1/4로 준다.
  - 이 흐름은 구간 요청을 못 받으므로 되감기는 웹이 `?t=초`로 새로 연다. 플레이어는 「시작 지점 + `<audio>`의 현재 시간」을 위치로 보여 주고, 길이는 색인의 길이를 쓴다. `player.seek()`과 잠금화면 위치 표시에 이 보정을 넣는다.
  - 원래 소리 파일(mp3, m4a, flac 등)은 떼어 낼 필요가 없으니 `serveFile`로 보낸다.
  - 판정에서 「그대로 보내기」를 고르면 소리 모드도 `serveFile`로 보내고 위 보정은 만들지 않는다.
- 다음 곡 미리 받기(`/api/prepare`)는 로컬 곡이면 색인만 확인하고 바로 답한다.
- `/api/radio`와 「뮤직비디오 찾기」는 로컬 곡에서 부르지 않는다. 곡 메뉴의 「유튜브에서 열기」도 로컬 곡에서는 숨긴다.

### 5. 유튜브 재생목록 가져오기
- `POST /api/import/youtube { url, name? }`: `yt-dlp -J --flat-playlist <url>`로 목록을 읽어(곡 저장 없음) 같은 이름의 재생목록을 만들거나, 이미 있으면 빠진 곡만 뒤에 더한다. 비공개·삭제된 항목은 건너뛰고 건너뛴 수를 돌려준다.
- 받는 링크: `youtube.com/playlist?list=`, `music.youtube.com/playlist?list=`, `watch?v=…&list=…`(재생목록 쪽으로 읽음), 앨범 재생목록(`OLAK5uy_…`). 「좋아요 표시한 동영상」·「나중에 볼 동영상」처럼 로그인이 필요한 목록은 이번 범위 밖이다(서버에 유튜브 로그인이 없음).
- 검색창에 재생목록 링크를 붙여 넣으면 결과 맨 위에 「재생목록으로 가져오기(N곡)」 칸이 뜬다.

### 6. 서버에 받아 두기
- `POST /api/keep/:id`: `yt-dlp -f 140/bestaudio[ext=m4a]`로 `/mnt/backup8t/orca-data/musike/keep/<가수> - <제목> [<id>].m4a`에 받는다(태그 포함). 이 폴더는 「받아 둔 곡」 뿌리로 색인된다.
- 받아 둔 유튜브 곡을 틀면 `/api/stream/<유튜브 id>/audio`가 유튜브 대신 그 파일을 보낸다(파일 이름 끝 `[id]`로 찾음). 재생목록의 곡 번호는 바뀌지 않는다.
- 곡 메뉴: 「서버에 받아 두기」 / 받는 중 표시 / 「받아 둠」 표시와 「받아 둔 파일 지우기」.

### 6-1. 누가 무엇을 하나 (사용자 11-18 확정)
어떤 기기도 다른 기기를 조종하지 않는다. "리모컨"은 B tv에 딸린 진짜 리모컨만 뜻한다.

| | 하는 일 | 하지 않는 일 |
|---|---|---|
| 서버 | 곡 파일·유튜브 받아 넘기기·재생목록·즐겨찾기 원본 | 소리 내기, 누가 무엇을 듣는지 알기 |
| 헤르메스(텔레그램) | 말로 정리(재생목록, 가져오기, 받아 두기), 「▶ 열기」 링크 | 재생·멈춤·다음 곡 |
| 폰 | 밖에서 듣기, 화면 꺼짐 재생, 손으로 넣기 | 다른 기기 조종 |
| 노트북 | 앉아서 듣기, 손으로 크게 정리(순서 끌기) | 다른 기기 조종 |
| TV | 리모컨으로 고르고 틀기, 영상 보기, 즐겨찾기 | 정리(재생목록 고치기·넣기·받아 두기·가져오기), 다른 기기 조종 |

### 7. 헤르메스(텔레그램)로 정리, 재생은 그 기기에서
- 사용자의 조작 창구는 텔레그램의 헤르메스다. 헤르메스는 텔레그램에서 서버 명령을 실행할 수 있다(`platform_toolsets.telegram: [hermes-telegram]`, terminal 포함). 기술 파일 `~/.hermes/skills/media/musike/SKILL.md`에 언제 쓰는지("음악", "재생목록", "노래", 유튜브 재생목록 링크 등), 서버 주소, API 표, curl 예시, 답장 모양을 적는다. 레포 `AGENTS.md`에도 같은 API 표를 둔다(다른 에이전트용).
- 헤르메스가 하는 일: 로컬 곡 찾기, 재생목록 만들기·이름 바꾸기·지우기, 곡 넣기·빼기·순서 바꾸기, 유튜브 재생목록 가져오기, 받아 두기, 목록 보여 주기. 답장 끝에 「▶ 열기」 링크(`/list/<번호>` 또는 `/play/<번호>`, Tailscale HTTPS 주소)를 붙인다. 링크를 누른 기기에서 재생된다.
- 하지 않는 일: 다른 기기의 재생을 원격으로 멈추거나 넘기기. 기기마다 재생 상태는 그 기기의 것이고, 서버는 재생목록·즐겨찾기만 같이 쓴다(사용자 11-18).
- yt-bulk가 같은 텔레그램 봇으로 받은 영상 알림을 보내므로, 그 알림 링크도 Musike `/play/…`로 바꾸면 한 창구에서 다 된다.
- 더하는 API: `GET /api/local?q=&root=`(로컬 곡 찾기·목록), `GET /api/local/roots`, `POST /api/local/rescan`, `PUT /api/playlists/:pid/tracks`(순서 통째로 바꾸기, 번호 목록).
- 웹 경로 `/play/:id`: 곡 정보를 찾아(로컬은 색인, 유튜브는 `/api/prepare`) 대기열에 넣고 바로 튼다. `/list/:pid`: 그 재생목록을 처음부터 튼다. 브라우저가 소리 자동 재생을 막으면 큰 재생 단추를 보여 준다.

### 7-1. TV(B tv 셋톱박스)
- B tv 스마트 셋톱박스(Smart 2·3 등)는 안드로이드 기반이고 APK를 직접 깐 사례가 있다. 기종은 아직 모른다(집 안 네트워크 검색에서 셋톱박스가 보이지 않음: 크롬캐스트 8008 없음, 켜진 기기 2대뿐). 먼저 사용자에게 기종과 TV가 서버와 같은 공유기에 있는지 확인받는다.
- 순서: (1) 셋톱박스에 TV 브라우저(예: TV Bro) APK를 USB나 원격 설치로 깐다 → (2) 서버의 집 안 주소 `http://192.168.0.43:4180`을 시작 페이지로 둔다 → (3) Musike가 TV(큰 화면·방향키)를 알아보고 TV 화면으로 연다(`web/src/tv/tvMode.ts`, 필요하면 `?tv=1`로 강제). TV에는 Tailscale을 깔지 않는다.
- 셋톱박스가 APK 설치를 막으면: 셋톱박스의 크롬캐스트로 폰 Musike를 보내는 길을 따로 검토한다(Musike가 집 안 주소로 보내야 함, 별도 이슈).
- TV에서도 재생 조작은 TV 리모컨으로만 한다.

### 8. 운영
- 서비스: `~/.config/systemd/user/musike.service`(지금 있음) — `pnpm start`, `HOST=0.0.0.0`, `PORT=4180`, 데이터 `~/.local/share/musike/data`(작은 JSON), 캐시 `MUSIKE_CACHE_DIR=/mnt/backup8t/orca-data/musike/cache`(HD 영상 캐시 2GB 상한, SSD 아님).
- PWA 설치(홈 화면 앱, 화면 꺼짐 재생에 유리)는 HTTPS가 필요하다: `tailscale serve --bg --https=4443 http://127.0.0.1:4180`. 테일넷 밖에는 열지 않는다(`funnel` 안 씀). 집 안 주소(http, TV용)는 공유기 안에서만 닿는다. 유튜브 약관상 남에게 공개하지 않는다.
- yt-dlp는 Musike 설정 화면과 별도로 매일 `yt-dlp -U`를 돌린다(유튜브가 바뀌어 끊기는 시간을 줄임).

### 9. 확인 방법
- 서버 단위 시험: 곡 번호 규칙, 파일 이름 → 제목·연도, 반쪽 파일 빼기, 재생목록 링크 읽기, 순서 바꾸기.
- 실제 서버: 「내 음악」에 타츠로 61개(중복 `_audiosr` 포함 여부는 색인 결과로 확인)·카시오페아 44개가 보임, 로컬 앨범과 유튜브 곡이 섞인 재생목록이 이어서 재생됨, 소리 모드 되감기.
- 폰: 안드로이드 에뮬레이터(`avd-up`)의 크롬에서 재생 → 화면 끄기 → 1분 뒤에도 재생 중(`dumpsys media_session` 상태)과 잠금화면 다음 곡. 실제 폰 확인은 사용자가 링크로.
- 화면: 390px·1280px로 「내 음악」, 섞인 재생목록, 가져오기 칸을 찍어 본다. TV 화면은 1920×1080으로 방향키만으로 재생목록을 골라 트는지 본다.
- 헤르메스: 텔레그램에서 "카시오페아 라이브만 모아 줘"를 보내 재생목록이 생기고 열기 링크가 오는지, 그 링크로 폰에서 재생되는지.
- TV: 셋톱박스에서 리모컨으로 재생목록을 골라 재생(사용자 확인, 그림 한 장).

## 위험

- 유튜브가 바뀌면 유튜브 곡이 잠시 안 나온다 → yt-dlp 매일 업데이트, 꼭 남길 곡은 「받아 두기」.
- 폰 브라우저가 화면이 꺼진 뒤 오래 지나면 재생을 멈출 수 있다 → PWA 설치를 안내하고 에뮬레이터로 확인. 그래도 멈추면 별도 이슈로 안드로이드 앱 판(이미 화면 꺼짐 재생 지원)에 서버 연결을 더하는 것을 검토한다.
- 셋톱박스가 APK 설치를 막거나 서버와 다른 네트워크에 있으면 TV는 이번에 못 할 수 있다 → 기종 확인을 TV 작업의 첫 단계로 두고, 안 되면 사용자에게 알리고 별도 이슈로 남긴다.
- 헤르메스가 말을 잘못 알아들어 재생목록을 지울 수 있다 → 지우기는 헤르메스가 한 번 되묻고, 서버는 `library.json`을 바꾸기 전에 하루치 사본을 남긴다.
- HDD(`/mnt/backup8t`)가 안 붙으면 로컬 곡이 안 나온다 → 「지금 못 읽음」 표시, 유튜브 곡은 그대로.
- 원작자 Musike가 바뀌면 포크와 어긋난다 → 서버판 변경은 새 파일 위주로 두고 기존 파일은 짧게 고친다.
