# Proposal: 곡 사이 페이드(겹쳐 넘기기)

## Why

이슈 #9: 곡이 바뀔 때 뚝 끊기고 다음 곡이 시작된다. 소리 모드에서 다음 곡을 몇 초 일찍 틀어 두 곡을 겹쳐 넘기면 듣기 편하다. 다만 같은 앨범 안의 곡(라이브 앨범, 이어지는 곡)은 지금처럼 그대로 이어져야 한다.

## What Changes

- 설정에 「재생 › 곡 사이 페이드」(0=끔 ~ 12초, 처음 값 4초)를 더한다. 값은 다른 재생 설정처럼 이 기기에 저장된다.
- 소리 모드에서 곡이 끝나기 N초 전에 다음 곡을 두 번째 `<audio>`로 시작하고, Web Audio 이득(GainNode)을 오디오 스레드에서 같은 힘(equal-power) 곡선으로 올리고 내린다. 화면이 꺼져 타이머가 느려져도 소리 곡선은 그대로 간다. 다음 곡이 소리를 내기 시작할 때 두 곡선이 시작된다.
- 유튜브 곡(구간 요청)과 로컬 곡(`?t=` 오프셋 스트림, 곡 길이는 색인의 길이)에 모두 된다. 대기열 순서·섞기·전체 반복을 따른다.
- 페이드하지 않는 경우: 한 곡 반복, 같은 로컬 앨범(앨범 이름과 가수가 같음)의 연속 곡, 영상 모드, 다음 곡이 없거나 라디오로 이어질 때, 다음 곡을 못 받을 때. 손으로 넘기기(다음·이전·곡 고르기)와 멈춤은 페이드 없이 바로 끊는다(겹쳐 있던 이전 곡도 바로 멈춤).
- 음량·음소거는 Web Audio를 쓰기 시작하면 마스터 이득으로 옮겨 그대로 동작한다.
- 서버(`streamLocalAudio`): `?t=` 오프셋 스트림이 영상의 이전 키프레임(카시오페아 mp4는 8.33초 간격)에서 시작해 소리가 최대 8초 일찍 나오던 문제를 고친다. 키프레임 쪽으로 `t`보다 최대 30초 앞에서 입력 `-ss`로 뛴 뒤 출력 `-ss`로 `t`까지 버린다(스트림 복사라 가볍다). 맨 끝 클램프(`min(t, 길이-1)`)는 그대로. 이 오차 때문에 되감기 뒤 페이드가 실제 끝보다 일찍 시작해 곡 끝을 잘라 먹었다.
- iOS 앱(네이티브 재생기), iOS 브라우저(화면이 잠기면 Web Audio가 멈춤), 안드로이드 앱(유튜브 주소를 직접 재생해 Web Audio가 소리를 못 읽음)에서는 설정이 보이지 않고 지금처럼 이어서 재생한다.

## Capabilities

### New Capabilities

- `crossfade`: 곡 사이 페이드.

### Modified Capabilities

- `local-library`: 소리 모드 되감기 위치가 정확해야 한다(±0.5초).

## Impact

- `web/src/player/crossfade.ts`(새 파일: 믹서와 조건), `web/src/player/player.ts`(오디오 두 대, 페이드 시작·정리, 음량), `web/src/lib/audio.ts`(`canMixAudio`)
- `web/src/components/FadeSection.tsx`(새 파일), `web/src/components/SettingsDialog.tsx`, `web/src/i18n/{ko,en,pt}.ts`
- `server/src/local.ts`(오프셋 스트림 `-ss`). API 변경 없음.
