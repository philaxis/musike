# Design: 곡 상자·꼬리표·묶음 + 유튜브 계정

## 원칙
혼자 AI로 관리하는 수준(사용자 11-18). 구조는 넷뿐이다: 곡 상자(출처), 꼬리표(자유 글), 재생목록(이미 있음), 묶음. 판단(무슨 작품인지, 어디 넣을지)은 코드가 아니라 헤르메스가 한다. 코드는 저장하고, 보여 주고, 거르고, 트는 것만 한다.

## 1. 곡 상자
- 저장: 데이터 폴더 `box.json`(원자적 쓰기, 하루치 사본은 `library.json`과 같은 방식). 항목: `{ track, sources: [{ kind, ref, name, at }], tags: string[], addedAt, gone? }`.
  - `kind`: `youtube-playlist`(ref = 재생목록 ID, name = 제목), `youtube-liked`, `local`(ref = 뿌리 이름), `link`(직접 넣음), `search`.
  - 같은 곡 번호가 다시 들어오면 출처만 더한다(곡은 하나).
- 내 음악 폴더의 곡은 따로 넣지 않는다. 상자 화면과 API는 로컬 색인을 `local` 출처로 함께 보여 준다(숨긴 것 제외, 숨기기 규칙을 따름).
- 화면: 보관함 「곡 상자」 → 거르기 칩(전체 / 정리 안 됨 = 꼬리표 없음 / 출처별 / 꼬리표별), 최근 들어온 순. 줄마다 출처 한 줄(예: 「유튜브 '좋은 노래' · 11-18」)과 꼬리표 칩. 여러 곡 골라 재생목록에 넣기(이미 있는 선택 기능).
- 유튜브에서 지워진 곡은 `gone: true`로 흐리게, 재생 시도 시 받아 둔 파일이 있으면 그걸로.

## 2. 꼬리표
- `tags`는 짧은 글 목록. 관례만 둔다(헤르메스 기술에 적음): `작품:`, `판본:`, `편곡:`, `작곡:`, `연주:`, `분위기:`, `장르:`. 화면은 `작품:` 칩을 앞에 둔다.
- 곡 메뉴 「같은 작품 다른 버전」: 같은 `작품:` 꼬리표를 가진 곡들, 원곡 줄 먼저, `편곡:`이 있는 곡은 아래 「편곡」 칸에.
- 손으로 고치기: 곡 메뉴 「꼬리표」에서 더하고 빼기(폰·노트북). 주된 길은 헤르메스.

## 3. 묶음
- 저장: `library.json`의 `bundles: [{ id: "B"+20자, title, artist?, parts: Track[], tags }]`.
- 재생목록·즐겨찾기·대기열에는 묶음이 곡 한 줄처럼 들어간다(`Track.kind = "bundle"`, `Track.id = 묶음 번호`). 재생할 때 플레이어가 부분들로 펼쳐 차례로 튼다. 부분 사이 페이드 없음(#9 페이드와 연동).
- 「다음 곡」은 다음 부분으로, 묶음 줄 메뉴의 「묶음 건너뛰기」는 묶음 다음으로. 진행 막대는 지금 부분 기준, 제목 줄에 「2/4 · 2악장 Andante」.
- 화면에서 묶음 줄을 누르면 부분 목록이 펼쳐진다(접힘 기본: 재생목록 안에서만, 페이지 전체는 펼쳐 둠 원칙과 별개로 줄 단위).

## 4. 유튜브 계정 연결
- 기존 OAuth 웹 클라이언트(구글 클라우드 프로젝트 `engaged-booth-512007-v1`, 「Playlist Library Web」)를 쓴다. 범위는 `youtube.readonly`만.
- 사용자가 구글 클라우드 화면에서 한 번: (1) OAuth 동의 화면을 「프로덕션으로 게시」 — 시험 모드는 7일마다 승인이 끊긴다(지금 MCP 승인이 그렇게 만료됨), (2) 승인된 리디렉션 URI에 `https://philaxis-b760m-aorus-elite.taildeaa80.ts.net:4443/api/google/callback` 더하기. 판정 페이지에 따라 누르기 안내를 둔다. 게시해도 「확인되지 않은 앱」 경고가 한 번 뜨지만 본인만 쓰므로 그대로 둔다(심사 안 받음).
- 설정 「유튜브 계정 연결」 → 구글 로그인 → `/api/google/callback`이 리프레시 토큰을 `~/.config/musike/google.json`(0600)에 둔다. 레포·데이터 폴더에는 비밀값을 두지 않는다.
- 읽기: `playlists.list?mine=true`(비공개 포함), `playlistItems.list`, `videos.list?myRating=like`. 하루 할당 10,000 중 재생목록 50곡당 1. 넉넉하다.

## 5. 매일 가져오기와 알림
- `POST /api/google/sync`: 연결된 계정의 모든 재생목록과 좋아요 목록을 읽어, 상자에 없는 곡만 넣고 출처를 기록한다. 결과 `{ added: [{ id, title, source }], gone: n }`.
- 매일 06:30 헤르메스 cron 작업 하나: sync를 부르고 → 새 곡에 꼬리표를 붙이고 알맞은 재생목록에 넣거나 새 재생목록을 제안하고 → 텔레그램으로 "새로 N곡 들어왔어요. 이렇게 정리했어요(…)" + 열기 링크. 새 곡이 없으면 보내지 않는다.
- 한 번에 아주 많이 들어오면(첫 가져오기 등) 헤르메스는 출처별 개수만 알리고 "정리해 줘"를 기다린다.

## 6. 기존 기능과의 관계
- 붙여 넣은 재생목록 링크(로그인 없음, yt-dlp)는 곡 수와 상관없이 「곡 상자로 들여오기」 단추 하나. 재생목록은 만들지 않는다. 기존 「재생목록으로 가져오기」 API는 헤르메스용으로 남긴다.
- 설정 「내 유튜브 재생목록」: 재생목록마다 체크박스(기본 켬). 끈 목록은 `~/.local/share/musike/data/google-exclude.json`에 ID로 저장하고 sync가 건너뛴다. 이미 들어온 곡은 그대로.
- TV: 곡 상자는 보이지 않는다(TV는 틀기만). 묶음은 TV에서도 한 곡처럼 튼다.

## 위험
- 사용자가 게시·리디렉션 등록을 못 하면 매일 가져오기는 7일마다 다시 로그인해야 한다 → 안내 페이지와 헤르메스의 "다시 연결해 주세요" 알림.
- 상자가 수천 곡이면 화면이 느릴 수 있다 → 서버에서 거르고 페이지 단위로 준다(한 번에 200줄).
- 헤르메스의 꼬리표가 틀릴 수 있다 → 사용자가 말로 고치고, 손으로도 고칠 수 있다. 꼬리표는 화면 표시와 찾기에만 쓰이고 아무것도 지우지 않는다.
