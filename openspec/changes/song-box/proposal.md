# Proposal: 곡 상자·꼬리표·묶음 + 유튜브 계정 재생목록 매일 가져오기

## Why

사용자 11-18(이슈 #12): "하나의 재생목록에 곡 엄청 많이 넣어놔서, 그걸 그대로 듣지는 않을 것 같고, 내부에서 source가 어디인지 정도만 기억해 놓고, 우리 서비스 안에서 헤르메스가 잘 구조화해 놔야 할 듯", "앱 서비스를 만들려는 게 아니라, 나 혼자서 AI를 통해 부담 없이 관리하고 이용할 수 있는 수준". 클래식은 "하나의 곡 객체를 알아서 하나의 교향곡 전체로 묶어" 듣고 싶다(#10).

지금 Musike에는 재생목록·즐겨찾기만 있어서, 유튜브의 큰 재생목록을 가져오면 큰 재생목록이 하나 더 생길 뿐이고, 곡이 어디서 왔는지와 무슨 곡인지(작품·판본·편곡)를 적어 둘 곳이 없다.

## What Changes

- **곡 상자**: Musike가 아는 곡 전부를 담는 창고. 내 음악 폴더의 곡과, 가져온 유튜브 곡이 들어간다. 곡마다 출처(유튜브 재생목록 이름·ID·가져온 날, 내 폴더 뿌리, 직접 검색·링크)를 하나 이상 기억한다. 듣는 목록이 아니다. 보관함에 「곡 상자」 칸(최근 들어온 순, 출처별, 꼬리표별, 정리 안 된 것만)이 생긴다.
- **꼬리표**: 곡마다 자유 글 몇 개(예: `작품:Asayake`, `판본:1985 라이브`, `편곡:브라스`, `분위기:밤`). 정해 둔 종류는 없고, 헤르메스가 붙이고 고친다. 화면은 곡 아래 작게 보여 주고 꼬리표로 찾고 거를 수 있다.
- **묶음**: 여러 곡을 순서대로 한 곡처럼 다루는 것(교향곡 악장 4개, 라이브 공연 앞뒤 곡 등). 재생목록·대기열에 한 줄로 들어가고, 펼쳐 볼 수 있고, 안에서는 페이드 없이 이어서 재생한다. 헤르메스가 만든다.
- **유튜브 계정 연결**: jordy4777@gmail.com 구글 로그인(읽기 전용 `youtube.readonly`). 사용자의 재생목록 목록(비공개 포함)과 「좋아요 표시한 동영상」을 읽는다. 「나중에 볼 동영상」은 유튜브가 API로 주지 않아 뺀다.
- **매일 가져오기**: 하루 한 번 연결된 계정의 재생목록에서 새로 들어온 곡만 곡 상자에 넣고(출처 기록, 곡 저장 없음), 헤르메스가 텔레그램으로 "새로 N곡 들어왔어요"와 함께 정리(꼬리표, 재생목록 나눠 넣기)를 해 둔 결과를 알린다. 유튜브에서 지워진 곡은 상자에서 지우지 않고 「유튜브에서 사라짐」 표시만 한다.
- **기존 「재생목록으로 가져오기」**: 링크 하나 가져오기는 그대로 두되, 큰 목록(기본 50곡 넘음)은 재생목록 대신 곡 상자로 넣을지 묻는다.
- **헤르메스 기술**: 곡 상자 읽기·꼬리표·묶음·재생목록 만들기와 "새로 들어온 거 정리해 줘" 흐름을 더한다.

## Capabilities

### New Capabilities

- `song-box`: 곡 상자와 출처.
- `tags`: 꼬리표.
- `bundles`: 묶음.
- `youtube-account`: 구글 로그인과 매일 가져오기.

### Modified Capabilities

- `youtube-playlist-import`: 큰 목록은 곡 상자로 넣을지 묻기.
- `agent-control`: 헤르메스가 곡 상자·꼬리표·묶음을 다루고 매일 정리 알림.

## Impact

- 서버: 새 `box.ts`(곡 상자·출처·꼬리표 저장), `bundles.ts`, `google.ts`(OAuth·토큰·재생목록 읽기), 매일 가져오기 작업, API 몇 개.
- 웹: 보관함 「곡 상자」, 곡 줄 꼬리표, 묶음 줄(펼치기·한 곡처럼 재생), 설정의 「유튜브 계정 연결」.
- 운영: 구글 클라우드 승인 앱을 「게시」로 바꾸고 돌아오는 주소 등록(사용자 계정에서 한 번), 헤르메스 기술 파일, 매일 작업(systemd 타이머).
- 하지 않는 것: 작품·녹음 표, 자동 짝짓기, 인명 사전, 표지 손관리, 유튜브 쪽 재생목록 고치기(읽기만).
